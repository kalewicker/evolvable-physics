# P01g: can the v2 sampler reach the mechanisms its templates permit?

Registration and sampler structural review, 2026-10-20. P01f established attached
birth, child-funded construction and leaf recycling in 48 authored fixtures.
P01g asks whether the specified hash-keyed distribution encounters useful
combinations without authored laws, favorable initial states or post-hoc repair.
The [protocol](p01g_protocol.json) is fixed before any sampler call. This milestone
implements and structurally tests the samplers; it admits no law draw or native
trajectory. The fixed campaign and event-level extraction are still pending.

## Fixed panel and decision

Use proposal IDs 4000 through 4015 inclusive under `p01-generator-v2`, crossed
with initial-state IDs 0,1,2,3, in that order. Each trajectory requests 128 epochs.
The denominator is 16 law cells / 64 trajectories / 8,192 requested epochs.
IDs were selected as a new contiguous development panel without drawing or
inspecting any resulting rule table. The namespace changes the draw identities;
there is no matched v1 comparison. Hash collisions, duplicate bodies, duplicate
tables, negative outcomes, missing cells and inconclusive labels stay visible.

An engineering pass requires every fixed horizon to complete, independent
Rust/Python generation and replay agreement, full detector records, valid
event-level mechanism evidence and compliant provenance/resource receipts.
Censoring is retained and independently checked but fails that completion gate.
An interrupted/failed batch is not resumed and missing cases are not replaced.

The mechanism continuation criterion requires at least two distinct ordered rule
tables with an actual attached funded newborn included in both estimators'
eligible proposals at the same sample. At least one of those tables must also
produce a loop in which that same newborn is later recycled in that same
trajectory. Different children or different initial states cannot supply halves
of a loop. Duplicate tables count once, including duplicates under different
proposal IDs. Four initial states are nested conditions, not independent law
samples. Additional Structural funding and child-funded construction remain
separate descriptive endpoints; they cannot replace a missing primary loop.

These thresholds are engineering choices for whether another bounded development
study is worthwhile. They are not significance thresholds or claims of sustained
organization. A mechanism miss stops escalation of this distribution pending
read-only diagnosis and an explicitly justified redesign; an engineering failure
requires diagnosis of feasibility/infrastructure. Passing both permits proposing
a fresh development protocol, not automatically launching E01 or expanding this
panel. Report descriptive fractions only for this fixed deterministic panel.

## Reachability and interpretation before sampling

The unchanged v2 design preserves eight initial Contact-ring nodes and a closed
activation budget of 64. The per-birth Burn gives a conservative upper bound of
64 births per trajectory; funded birth and recycling cannot provide indefinite
constructive turnover. Resource transfer activity remains excluded. Original
nodes retain immutable Contact incidence, nonleaf deletion fails and edge-only
detachment can strand an orphan. Those are retained distribution constraints.
Future mechanism extraction must reconstruct individual committed operations and
states: available rules or activity pooled over a component are insufficient.

The frozen detector supplies eligibility, complete AP records and disagreement
labels. Full-horizon AP is null on censoring. It is not a substitute for physical
birth/funding/deletion evidence. This preflight establishes neither maintenance,
causal reproduction, heredity nor adaptation. A supplied-resource maintenance
assay needs a separately registered environment design.

## Implementation and review scope

`src/bin/generator-v2.rs` constructs v2 environments using the frozen core types
without modifying the original library, Cargo files or v1 sampler. Its SHA-256
key tuple, first-16-hex parsing, modulo reduction, initial draw labels, rule
multiplicity and inventory formulas follow the source contract. Changes from v1
are the namespace, Structural transfer route, integrated funded attached birth,
and leaf recycling with Burn. Rule fields use initial=0; only initial-world and
scheduler fields use the selected initial-state ID. Unused draws have no effect.

`scripts/generator_v2.py` implements that distribution independently in Python
using the standard library. Both CLIs require a future separate admission bound
to the exact protocol bytes and fixed slot before constructing a hash-keyed law.
The future campaign must additionally verify the complete execution freeze.

Three Rust tests and the Python sampler tests inject literal field values. They
exercise all eight templates, both routes, wildcard/concrete states, field
boundaries, sign, resource inventories, allocator positions and invalid initial
IDs without using the hash-keyed draw path or applying any rule. Mock decision
tests reject pooled children, pooled initial states, duplicate tables, censored
gate observations, unborn IDs, changed law identity and altered denominators.
Source inspection checks the keyed SHA/modulo implementation against the v1
construction and immutable v2 specification. This is not measured agreement on
any sampled law; full Rust/Python initial-state equivalence remains an execution
gate for every future panel cell.

## Execution preparation and cost policy

Reuse the frozen worker, Rust reporter, original Python interpreter, separate
single-pass adapter, watchdog and accounting. New files must implement only the
fixed campaign orchestration and event-level mechanism checks. Freeze their full
source/dependency/binary/input closure and write a separate execution admission
before any registered law construction or trajectory, including rehearsals/tests.
Do not add another general runner framework or edit a frozen source path.

The fixed ceilings are 600 seconds wall, 300 seconds aggregate process CPU and
1 GiB retained artifacts, with 32 MiB reserved for metadata. Generation/native/
Rust-report/Python-audit process wall limits are 5/10/20/30 seconds. Each worker
allows 16,384 events and 4 MiB whole-epoch trace bytes. This is a small cost
preflight, not a promise that every cell will fit. Stage launch reservations and
all censored/unstarted cases must remain visible. Record complete pipeline cost,
stage costs, RSS and output; do not extrapolate P01f witness timing to this panel.
Memory enforcement is sampled with a reaped-peak check, not an instantaneous
hard bound. All concrete limits and decision rules are in the immutable protocol.
