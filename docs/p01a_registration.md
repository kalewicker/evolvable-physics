# P01a: generator and cost preflight

Registered 2026-10-19 before execution. This closes a bounded engineering milestone; it does not execute the full proposed P01 pilot. The machine-readable panel and ceilings are in `p01a_protocol.json`. All 16 proposal IDs crossed with four initial states are retained, including duplicate laws, invalid outcomes, cap hits and slots not started before the campaign ceiling. There is no rejection sampling, repair, seed substitution or threshold adjustment. A failed gate remains failed.

## Generator v1

Every draw is the first 16 hexadecimal digits of SHA-256 of canonical JSON `["p01-generator-v1", proposal, initial, field, index]`, interpreted as an unsigned big-endian 64-bit integer, modulo the stated range. Modulo bias is part of this distribution. Rule draws use initial=0, so the four states share exactly the same eight laws. IDs identify draws, not random independent observations of all possible physics.

For each rule index 0..7, `form` modulo 8 selects: unary SetState, unary AddState, unary Burn, Contact-pair Transfer, unary CreateNode, Contact-pair CreateEdge, Structural-pair DeleteEdge, or Structural-pair DeleteEdge followed by DeleteNode. The last form deletes slot 0 to slot 1 after refunding the edge to slot 1. Kind fields `kind0`, `kind1`, `new_kind` are 1+draw modulo 3. `state0` and `state1` are modulo 4: 0..2 require that state; 3 is wildcard. `value` is modulo 3; `sign` modulo 2 is -1 or +1; `amount` is 1+draw modulo 2; transfer `matter` is modulo 2. Pair patterns have ordered slots [0,1], kind-0 edges. Creation requires the identical Structural edge absent. Unused fields do not affect a proposal. Native checked execution rejects inapplicable operations without repair.

Initial states contain eight nodes with `node_kind`=1+draw modulo 3 and `node_state`=draw modulo 3, eight free matter and eight activation each. Eight directed kind-0 Contact edges form a ring. `structural` modulo 2 independently decides each parallel Structural edge; their IDs are sequential starting at eight. Matter totals include every bound node and edge. Scheduler seed is draw(`scheduler`, index 0) modulo 2^64-1. No channels are applied: this first distribution uses the admitted closed environment wrapper. It does not cover the full grammar or driven environments. Contact-ring nodes cannot be deleted while Contact edges remain, so the DeleteNode template can be inapplicable; this bias is disclosed and is not repaired.

Native caps are 4,096 applicable-candidate limit, 65,536 partial binding pushes, 128 nodes and 256 edges. The original matcher actually charges all full pattern matches, including operation-inapplicable matches, against its candidate cap. Reported `applicable_candidates` counts only the returned applicable candidates; it is not the number of partial bindings or all pattern matches.

## Controls and accounting

A fresh `pilot-worker` subprocess handles each slot. It streams full canonical environment epochs one per line. Whole environment epochs are staged: the total-event ceiling includes native plus applied external events; exceeding it discards the staged epoch. The trace ceiling includes each newline; a rejected epoch changes neither the last exported state nor its event count. Summary output is separate. Exact event/trace limits permit equality. Existing matcher/world limits remain unchanged. Interrupted output may end in a partial record: it is retained and marked interrupted, never accepted as a complete trace.

The supervisor kills and reaps a worker on wall-clock expiry or a sampled RSS overrun. RSS is sampled with `ps`, in KiB converted to bytes, with a target 10 ms polling delay plus command overhead. This is a sampled watchdog, **not a hard maximum on instantaneous memory**: brief peaks can be missed, and overshoot is possible. Final child peak RSS comes from `wait4` (bytes on macOS, KiB on Linux). CPU user+system time is also from `wait4`. These controls target macOS/Linux, and guard tests must pass on the execution host. A total-memory guarantee is not established. No child descendants are launched by the worker.

Campaign launch checks reserve each next worker's full registered time/trace allowance before starting it, and require at least its wall allowance in the remaining worker-CPU budget (one single-thread worker). Crossing a campaign limit leaves remaining fixed slots `not_started_campaign_budget`, rather than replacing them. These are conservative admission checks, not guarantees on Python/OS overhead. Source snapshot, binary/platform/protocol hashes, original outcomes, exact output bytes, process metrics, and all source/trace checksums are retained in a new directory. The output directory must not exist.

Record full-step wall time (including wrapper validation, atomic staging, matching, commit and full trace construction), JSON serialization, and output writes separately. These are observer-inclusive timings, not native phase timers or quiet-mode throughput. `step_ns` includes work on a rejected event-cap epoch; exported counters describe committed epochs only. Audit and supervisor overhead are outside worker phase timings and inside campaign elapsed time. CPU excludes the parent and `ps` processes. Record duplicates using rules with IDs removed; do not discard them.

Independently regenerate every initial environment in Python and replay every committed epoch using the admitted Python interpreter, checking candidates, priorities, dependencies, state, ledgers, counters and final identity. Deliberate corrupted traces/initial states must be rejected. Force event/trace caps with a known active oscillator and verify rollback; force wall and RSS watchdogs with a sleeping child. Verify nonzero worker failures are infrastructure errors. These forced controls are separate from the 64-slot panel.

Gate: all 64 registered slots complete, independent generation and replay pass, all guard checks pass, all frozen P00 contracts match. Detector thresholds stay frozen. A cost gate failure or cap hit is reported without rerolls. Output counts and cost estimates are development observations, never prevalence, useful mutation, maintenance, adaptation or discovery evidence. This milestone does not run detectors on generated trajectories or establish calibrated detector generalization to this distribution.

The next decision is a separate full-P01 registration with total budgets, slow-tail treatment and detector reporting. Linear 1,000-epoch projections from 64-epoch runs are labeled scenarios only: graph growth, matcher cost and rare trajectories can invalidate them. The observed maximum is not a tail bound. P01 readiness remains false until that registration and explicit memory-policy decision are recorded. E01 remains unauthorized.
