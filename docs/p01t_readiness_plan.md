# P01t saved-input transport readiness registration

2026-10-24. Register the complete fixed saved panel before implementing or running
retained-envelope conversion. The expected nested wrapper and pair agreement are
already known from P01r; this is engineering readiness, not a blind scientific test.

## Scope and admission

After registration commit/push, implement only the three new paths in the protocol.
The producer may import only the two explicitly frozen P01s boundary/accounting
modules plus standard library; never import old generators, campaign runners or
native wrappers. The auditor imports neither producer nor those two modules and
must implement its own strict parser, typed comparison and request oracle. No
process creation, keyed generator evaluation, rule applicability, candidate match,
semantic worker validation, stage process, benchmark or world transition is allowed.
The request's epochs=128 is an inert field; executed epochs remain zero.

First test invented fixtures in normal and optimized Python, preserving all logs,
fixture packet, source snapshots and test receipts. Test the real bytes-to-request
boundary without mocking away the envelope reader. Pin and verify tested source
identities before retained parsing. Retained conversion may begin only with all
registered controls passing; the independent auditor must itself pass mutation
tests before it checks the real outputs. No implementation or conversion this turn.

## Fixed input panel and transformation

Use all 32 proposals6000..6031 and initials0..3 in proposal-major order, slots0..127.
Read both already saved P01o Rust/Python generation stdout files per slot; never
regenerate or substitute an input. Pin all256 bytestring digests, both original
inventories/seals, P01s final source identities and closure history. Every slot is
present in the manifest before work. No prefilter, favorable-law selection or
exclusion is permitted. A failure retains that slot as failed and later slots as
unstarted; 128 remains the denominator. Full success requires all128, with no
missing, duplicate or extra slots/requests.

Verify byte hashes before parsing; enforce the 1 MiB per-stream cap before reading
payloads. Reject duplicate keys, nonfinite numbers including overflow, malformed
JSON, wrong schema/cell identity and any typed stream disagreement. Booleans,
integers and floats are distinct; object key order is immaterial, array order is
not. Preserve the complete parsed envelope and expose exactly environment, with
its nested native object, as request.initial. Preserve every field, rule, resource,
map, draw record and metadata value without interpreting them. The frozen adapter
constructs exactly schema, initial, epochs, max_events and max_trace_bytes; all
five fields and types must equal the registered contract and source environment.

Serialize requests deterministically as strict JSON and parse them back for typed
equality. Re-serialization changes whitespace/key order, so do not claim byte
identity between saved streams and requests. Original stream bytes remain untouched
and are identified by their own SHA256. Keep both input hashes, typed equality,
complete-envelope and nested-environment canonical digests, request file digest,
request size, slot/proposal/initial and status in each row. Canonical digests use
UTF-8 JSON with sorted keys, separators comma/colon, ensure_ascii=false and
allow_nan=false; they supplement, not replace, independent typed comparisons.

Requests and full environments stay in ignored local artifacts. Public receipts
contain hashes, sizes, identities, status, controls and audit results only. No
raw retained request or saved environment is published.

## Accounting, limits and terminal behavior

Each producer/auditor has a cooperative 120-second and 128-MiB output limit; reserve
5 seconds and 1 MiB for terminal records. A request is capped at 512 KiB. Reject
limits at equality for ordinary work. Limits are prospective, not measured speedups,
and do not claim hard CPU/RSS isolation. Use measured monotonic elapsed time and
maintained byte totals; polling performs no filesystem access. Count input reads,
hash-read bytes, output writes, stat calls, ledger updates, budget polls and scans.

Perform a single deduplicated custody pass per tool. Original inventory membership
and hashes are checked before retained work; cache only the bounded256 stream
bytes for conversion so custody does not cause repeated payload reads. Input hash
work is distinct from output scans. Do not repeat original custody during terminal
closeout. The producer checks the newly created empty output root once; the
independent auditor performs one complete output inventory. Declared input bundle
membership scans are reported separately. No stage directory/process is needed.

Reserve bytes before each output operation, including source snapshots, request
serialization, logs, checksums and completion. Actual partial writes remain in the
ledger. Failure closeout uses maintained paths and all128 initialized rows, never
a tree scan. Preserve first error separately from subsequent closeout errors. If
exact output accounting is unavailable, report null plus a justified conservative
bound and incomplete reconciliation; never present known-path bytes as a total.
If even terminal persistence fails, the outer harness/test receipt must explicitly
record that missing terminal artifact. Inventory excludes its own bytes and the
completion file from hashing; exact independent membership and total bytes include
both. Hash the inventory in completion. Preserve failed and partial bundles.

## Fixed controls and independent acceptance

The protocol names 14 control families, to expand into fixed invented subcases
before tests. They cover:

1. Complete-envelope bytes through exact request and parse-back preservation.
2. All128 identities/order, including first/last and no selective omissions.
3. Bool/int/float disagreement and object-order versus array-order behavior.
4. Malformed JSON, duplicate keys, NaN/Infinity and exponent overflow.
5. Wrong digest, schema and slot/proposal/initial, including boolean IDs.
6. Missing/non-object environment/native and already-unwrapped input.
7. Extra metadata, maps and draw-record preservation.
8. Independent rejection of altered resource, rule, request schema and each cap.
9. Identical results from absolute and relative output paths.
10. Injected partial request-write failure with bytes retained/accounted.
11. Exhausted reserve and terminal I/O error, preserving the first error and all128.
12. Exact reserve boundary plus one unit either side for time/bytes; filesystem
    spies and forbidden-API traps for repeated budget polling.
13. Independent rejection of missing, duplicate, out-of-order and extra cell rows.
14. Independent rejection of changed bytes, unlisted/missing files, changed scan,
    write and ledger counters, and false exact totals after partial failure.

Acceptance requires all controls, normal/optimized tests, all128 exact requests,
both256 original identities, unmodified frozen sources, complete manifest membership,
exact file inventory/byte accounting and the independent audit to pass. Auditor
re-reads frozen input bytes independently, reconstructs expected requests without
producer imports, verifies metadata and every nested value, and checks the saved
serialized requests and file hashes. Counters are checked against independent
spies on fixtures and reconciled against retained receipts; self-reported pass flags
are insufficient. The auditor preserves its own source/input/test identities,
results, costs and completion receipt.

An unsuccessful attempt does not authorize changing the panel or relaxing gates.
Implementation-only repairs may repeat the same read-only transport test in a fresh
directory with every predecessor retained. A saved-input defect must stay failed;
repairing or replacing it needs a separate protocol. Passing stops at transport
readiness. Native acceptance, integration, performance and dynamics are not admitted.
P01q remains consumed and unrepaired; science untested, behavior null/not_executed,
and E01 unauthorized.
