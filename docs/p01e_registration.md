# P01e: offline verifier equivalence and paired cost

Registered implementation details, 2026-10-19, before any candidate execution on the fixed panel. The existing [protocol](p01e_protocol.json) is unchanged. Its post-hoc engineering panel and 20% summed CPU reduction gate are not changed after measurement. All fixed pairs and failures must be retained, without retries or substitutions.

`audit_single_pass.py` retains Python independence from the Rust transition engine. It uses the frozen Python operation interpreter, candidate enumeration, environment interpreter, physical-change definition, detector and whole-epoch cap builder. It combines the reference native-state replay and activity extraction in one checked event pass. It does not change the frozen reference files or connect to the native runner. Retained-epoch candidate preparation and the existing staged next-epoch cap justification remain necessary verification work.

Checks retained: profile and world validity; canonical complete records; before/after digests; full candidate enumeration, priorities and read/write sets; conservative scheduler selection and commit ordering; event IDs and dependency parents; atomic operation replay; resource accounting, writers, state and size bounds; channel order, external receipts, prepared state, full environment state and ledgers; worker summary counts/final state; trace/event/horizon caps and independent reason for censoring; complete detector records and null full-horizon endpoints for censored prefixes. No resource-only activity credit or detector threshold is changed.

The source/input freeze binds the candidate, harness, worker, receipt auditor, tests, reference dependencies, the original input inventories and selected input files before execution. Original campaign provenance is checked before paired processes. Execution uses source copies in a new output directory. The two P00 suite files are byte-bound to the sealed P00g inventory; the eight P01 inputs are byte-bound to their original campaign inventory. No missing draw is generated and no native world is evolved.

The one guarded fixture process compares all 112 native cases (state, event count, physical activity and detector records) and 96 environment cases (full environment states and detector records). The frozen environment fixture checks also validate their branch/maintenance records; candidate equivalence additionally covers the 16 warmups and 80 retained maintenance arms contained in those same 96 cases. This does not admit a new maintenance claim. The eight paired P01 processes double as the P01 correctness panel: both must verify the identical original full detector record, and their input/output/endpoint receipts must match exactly. They are not run an extra time for correctness.

Pair order follows the protocol, one reference/candidate pair per fixed slot. Child CPU includes imports, parsing, checked replay, detector construction, endpoint validation and common receipt hashing. Guard/parent/provenance overhead is included separately in aggregate campaign accounting, not in the paired leaf CPU ratio. No warmup, retries, outlier rejection, repeat timing or post-measurement candidate adjustment is allowed. Results are host-specific observations on this selected panel, not a representative speed estimate or a general cost-tail bound.

Each of the 11 corruption tasks uses the retained `driven_pair`, seed 0, primary environment case. A P01-shaped request/summary/report is assembled from its existing records with zero timing placeholders, then both verifiers must accept the clean control and reject the altered copy with AssertionError. Mutations are: candidate priority; dependency parents; omitted committed event; environment ledger; prepared state taken before the environment phase; external receipt digest; native world state; worker native-event count; detector disagreement flag; an unjustified claimed trace cap with an extended requested horizon; and a missing final newline. These correspond in order to all 11 protocol corruption names. The candidate must fail at the named check; the frozen reference sometimes supplies an empty assertion message, which is retained. Crashes, absent files or guard termination do not count as rejection.

The frozen campaign guard enforces the 90-second wall and 1 GiB sampled RSS ceilings and detects parent loss. The 1 MiB output allowance is divided into 960 KiB stdout and 64 KiB stderr, with no overflow accepted. The parent reserves 90 seconds wall, 180 seconds aggregate CPU and five seconds sealing allowance before a stage, plus 40 MiB for outputs/scratch/metadata. Paired children and guards are single-threaded; reservations are conservative launch checks. Final observed aggregate CPU/wall/artifact ceilings remain authoritative. RSS is sampled and is not a hard instantaneous memory bound. Fixed stages not launched because of any failure or reservation stop remain missing and fail admission.

The final seal anchors the manifest/inventory and accounts for its own bytes. `audit_p01e.py` checks full retained inventory, copied source identity, stage/output bindings, fixed pair order and denominator, corruption receipts, censored policy and CPU/resource gate arithmetic without rerunning either verifier. The source/input freeze and sealed bundle remain immutable. Later publication receipts/test logs stay outside the bundle.

This gate admits at most an engineering adapter on disclosed retained evidence. Passing does not replace the frozen P01 pipeline or authorize a new campaign, continuation, changed generator, detector, larger budget, or E01. On either outcome, next record findings and choose a separately registered next bounded step; do not optimize again against these timing results under this registration.
