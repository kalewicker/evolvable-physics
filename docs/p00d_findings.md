# P00d environment-aware branching and recovery findings

Date: 2026-10-17. Engineering component: passed. Full P00: incomplete. Scientific acceptance: untested.

Publication note: compact receipts and test logs are included under [evidence](evidence/README.md). Raw run histories, checkpoints, and original source snapshots remain local and are regenerated by the validation runner.

## Result

Environment-aware intervention requests now bind the complete wrapper, including the environment schedule, accounting ledgers, and native state. State/resource edits preserve the environment configuration, produce nested native and full-wrapper receipts, and occur before the next environment phase without consuming it.

Branch bundles publish their completion manifest last. Bundle admission checks all files and hashes and recomputes the requested transition; it cannot accept a forged receipt merely because its declared hash matches. Checkpoint publication now syncs the containing directory around pending-name cleanup.

Primary evidence: [manifest](evidence/p00d-001/manifest.json), [independent integrated audit](evidence/p00d-001/environment_branch_audit.json), `artifacts/p00d-001/environment_branches/suite.json` (local raw artifact), [Rust test log](evidence/p00d-001/tests.txt), and [checksums](evidence/p00d-001/checksums.json). Source snapshots, source/binary hashes, toolchain identity, prior-suite results, and rejection logs are retained.

## Fixed matrix and outcomes

Two fixture families × 16 seeds × five arms = 32 cases / 160 arms. Each source has two warmup epochs and each arm has six continuation epochs. Independent replay checked all 960 continuation epochs, 1,728 native events, and 6,400 environment events, plus source warmup and intervention receipts. No seed, arm, criterion, or unfavorable outcome was replaced.

The fixture contains two disjoint, identically configured driven paths. Corresponding nodes match in type, state, balances, and contact degree. In the state-arrest family, the target oscillator is changed from state 0 to 9. In the replenished-activation family, two activation units are moved from its reservoir to an inert holder.

| Arm | State-arrest focal/control firings | Replenished-activation focal/control firings |
|---|---:|---:|
| baseline | 6 / 6 | 6 / 6 |
| sham | 6 / 6 | 6 / 6 |
| target | 0 / 6 | 6 / 6 |
| unrelated | 6 / 0 | 6 / 6 |
| immediate rescue | 6 / 6 | 6 / 6 |

These outcomes held for every registered seed. The activation-removal null effect is expected: scheduled supply replenishes enough activation for firing. Its inventory distribution still differs from baseline, so equal firing counts do not establish equivalent full state. Sham and rescue match baseline physical trajectories while retaining distinct intervention provenance.

## Verification

All 28 Rust test entries passed (27 substantive tests plus the child-process fault-injection helper). Formatting and Clippy with warnings denied passed. The original kernel, native-intervention, and environment suites also passed; their emitted suite files remain byte-identical to P00c.

The independent Python checker reconstructs wrapper-bound edits, receipts, source identity, schedule/ledger preservation, every environment phase, and every native continuation. Eight tampered trace cases were rejected: source, schedule, ledger, operations, receipt, missing rescue step, native phase, and environment phase.

Fresh CLI processes applied and resumed target and rescue bundles for both families and matched full expected environment checkpoint payloads. Schedule-only source changes invalidate stale requests even with identical native state. Existing bundle directories cannot be overwritten.

Six malformed/incomplete bundles were rejected by both Rust admission and Python verification: missing manifest, missing record, truncated record, forged receipt with an updated declared hash, schedule drift, and noncomplete manifest. No continuation output was published for these failures.

## Interrupted publication

The Rust fault-injection test starts a separate child process and exits it with code 71 after each publication boundary: source checkpoint, branch record, resulting checkpoint, and completion manifest. Bundle admission rejects the first three states and accepts the fourth with exact source identity. These are actual process exits, not just returned errors. A separate test verifies that a partial pending checkpoint blocks publication and remains unchanged.

Artifacts from these process-boundary tests are retained in temporary `p00d-recovery-<pid>` / `p00d-pending-<pid>` directories. The sealed run includes test source and passing logs; the temporary files are not part of the sealed bundle inventory. Adversarial incomplete-bundle copies and their rejection logs are retained inside the sealed validation bundle.

Directory syncing and process-exit testing do not certify arbitrary power-loss behavior, faults within every filesystem call, or complete event-store crash recovery. A standalone checkpoint is not a substitute for its retained ancestral intervention/trace records.

## Scope and next boundary

This result validates controlled engineering machinery, not biological individuality, self-maintenance, reproduction, adaptation, or useful artificial physics. Rescue is immediate reversal before continuation, not recovery after a prolonged damaged trajectory.

The next bounded P00 task is detector specification and calibration: implement structure tracking and maintenance endpoints, register positive/adversarial fixture expectations, retain detector disagreements, and test false positives. Full P00 remains unaccepted until those assay gates pass. No P01 pilot or E01 census has started.


```sh
python3 scripts/audit_environment_branches.py artifacts/p00d-001/environment_branches/suite.json
```
