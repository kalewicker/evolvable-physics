# P01c: sealed campaign runner readiness

Registered 2026-10-19 before control execution. This milestone implements the existing P01 protocol and tests engineering controls; it does not evaluate any of its 512 full-pilot slots or change any earlier freeze. Full execution requires the successful current P01c receipt.

Each slot's independent Rust generation, native worker, Rust replay/detection and Python independent audit are guarded separately. Generation and native processing share the native 10-second allowance. The independent Python generator checks Rust's initial state; the independent audit binds the request, trace and detector report before a slot receives any full-horizon endpoint. Sources and release binaries are copied into the campaign directory before execution; analysis runs from those copies. The campaign uses the unchanged registered proposal-major ordering and keeps every slot in a preallocated ledger.

## Resource and publication policy

Keep P01's 100-second full-slot wall/CPU launch reservation, registered trace/artifact caps and 16 MiB metadata reserve. Per-slot artifact reservation is native trace ceiling + Rust report ceiling + Python audit ceiling + 3 MiB for generation, request, summaries, logs and stage metadata. Generation output/request is at most 256 KiB, native summary at most 256 KiB, and each other child stderr at most 64 KiB. Generation stdout is at most 256 KiB. Parent metadata/source preparation is charged from source snapshot start; builds and hash/readiness checks occur before campaign time starts. All retained copies, logs and source/binary snapshots count as file bytes. No raw trace is copied into a second alias.

The guard drains child pipes into exclusive files. It retains only the registered maximum prefix of each stream, records observed-versus-retained byte counts, kills/reaps on excess, and classifies the output as unmeasured. An unread pipe suffix is unknown, not a deleted unfavorable outcome. It also polls sampled RSS, checks wall/global elapsed deadlines, and records child and guard CPU separately. Aggregate campaign CPU is parent self + reaped child/descendant usage; individual child timings are descriptive and never added again. Stage wall/CPU admission checks are conservative and repeated between stages. Single-thread child computations and sampling delays mean small overshoots remain possible; all observed overshoots are reported.

A separate guard checks its original parent PID. On campaign-parent loss it kills/reaps the child and writes its own receipt. The parent waits for the guard; ordinary exceptions/interrupts terminate the guard gracefully so it can reap. Each stage is recorded as running before launch, and each endpoint is committed only after the independent audit's binding checks. A forcibly killed parent leaves an unsealed original manifest. A read-only audit classifies its active slot and all pending slots as interrupted/unstarted, exports no accepted scientific endpoint from that unsealed bundle, and never resumes or overwrites it. Arbitrary simultaneous guard/OS failure and power-loss durability beyond file/directory fsync remain unverified.

Publication uses fsynced atomic manifest replacement, an inventory and a final seal binding both. Inventory hashing/sealing work is charged; final resource measurements precede the last seal publication, whose small trailing overhead is explicitly excluded. The seal includes its own retained file size in artifact accounting. The final seal records any elapsed/CPU/trace/artifact overshoot. Budget stops preserve all slots and files. Infrastructure failures stop further launches; stage wall/RSS/output-cap outcomes are unmeasured and may proceed to the next registered slot if budget permits. Native semantic caps with a valid audited prefix remain censored. No partial success, invalid report or analysis timeout becomes a negative AP label.

## Fixed readiness controls

Use the already disclosed seed-0 driven-pair fixture for four control slots (4 states as ledger indices, same supplied fixture; these are not independent worlds). Baseline horizon: 12 epochs, event limit 200,000, trace cap 1 MiB per slot, native wall 2 s, Rust wall 3 s, audit wall 5 s; sampled RSS as registered for each stage. Control campaign allowance: 120 s wall, 120 s aggregate CPU, 8 MiB traces, 64 MiB artifacts, 1 MiB metadata reserve. Source/binary copies remain counted. Control overrides/fault injection are forbidden in full mode.

Check a complete four-slot campaign; injected between-stage budget stops (synthetic admission decisions, not measured resource exhaustion); zero-event and zero-trace native caps; exact aggregate trace and artifact launch boundaries; total CPU/wall/trace/artifact exhaustion; nonzero child failures in generation/native/Rust/audit; stdout/stderr overflow at every stage; RSS and wall stops; independent-audit failure after Rust success; missing summary/changed report; exclusive output paths and immutable source snapshots; guard observation failures and cancellation; and parent SIGKILL/loss while a guard is active. The last control must leave an unsealed manifest, a parent-loss guard receipt and no accepted endpoints in the read-only audit. Test the full 512-slot ordering without launching it. Costs are development/control measurements only.

The read-only audit verifies seal/inventory/source/binary identities, completed-stage receipts and audit bindings; it preserves censored/unmeasured/unfinished cells. Engineering acceptance requires all control expectations pass and all previous frozen files match. Acceptance admits only executing the registered bounded P01 development pilot next. It does not admit E01, detector accuracy on arbitrary laws, maintenance, reproduction, adaptation or search superiority. No full P01 run occurs during P01c.
